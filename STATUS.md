# Artifact status

We are applying for the **Artifacts Available** and **Artifacts Functional** badges.

## Available

The artifact is public at <https://github.com/kiSmetZz28/CESAL> under the MIT license, and
will be archived with a DOI (Zenodo) before the permanent-link deadline. It contains the
complete source for every component described in the paper: the EM-AT base learner, BAT and
Q-BAT ensemble construction, EM-GMM automated thresholding, the Mahalanobis routing policy,
the collaborative cloud–edge inference pipeline, the RAG-enhanced LLM open-set classifier,
and the Table 1 controlled-response workflows. The HDFS and OpenStack log splits and the
open-set knowledge base are bundled; pre-trained checkpoints are fetched by
`python run.py download`.

## Functional

- **Documented.** [README.md](README.md) explains the design and maps every paper section,
  table and figure to the code that implements it. [INSTALL.md](INSTALL.md) gives
  step-by-step setup, [REQUIREMENTS.md](REQUIREMENTS.md) states hardware, software, disk and
  expected runtimes.
- **Complete.** Every component described in the paper is present. No part of the pipeline
  is stubbed or withheld.
- **Exercisable.** [install.sh](install.sh) scripts the whole install and finishes by running
  the unit-test suite. Four per-claim scripts live in [artifact/claims/](artifact/claims/),
  one per paper claim. Pre-computed EM-GMM thresholds are committed, so inference runs
  immediately without retraining.
- **Scaled down.** A full HDFS run needs roughly a day of edge compute; a 300-window
  end-to-end path exercises all four stages in about two minutes
  (`artifact/claims/claim4_scaled_down.sh`).

## Reproduced — what to expect

We are not claiming the Reproduced badge, for reasons we would rather state plainly than
have a reviewer discover:

1. **Evaluation protocol.** Detection metrics are **point-adjusted**, following the Anomaly
   Transformer convention this code inherits: `training_pipeline/solver.py` (lines 394-412)
   fills an entire ground-truth anomaly segment once any line in it is detected. Both test
   splits are built as all-normal lines followed by all-abnormal lines
   (`cesal_core/data/loaders.py:45-53`), so each contains exactly **one** anomaly segment,
   and a single correctly flagged line inside it yields near-perfect recall. The claim1
   script prints raw and point-adjusted scores side by side so the difference is visible.
2. **Pre-computed per-model arrays.** `outputs/<dataset>/edge_preds_per_model.npy` and
   `cloud_preds_per_model.npy` are **downloaded assets** from the original experiment runs,
   not regenerated by the shipped pipeline; no code in this repository writes them. The
   dashboard reads them to display per-model votes. Treat them as recorded results, not as
   pipeline output.
3. **Hardware.** Table 6 (edge CPU/memory/latency on Raspberry Pi 3B+/4B/5) requires
   physical devices and cannot be reproduced on shared infrastructure.
4. **Gated models.** Two of the four LLM backbones in Table 7 require accepting Hugging Face
   licenses.

## Known issues

Open discrepancies between the shipped code and the paper, listed for transparency:

- `cesal_inference_pipeline/routing.py:135` sorts Mahalanobis distances with `reverse=True`
  and takes the top *M*, i.e. the samples **farthest** from the threshold vector, whereas
  Algorithm 3 and Section 3.6.1 specify `TopMSmallest` — the samples **closest** to the
  decision boundary.
- The Mahalanobis covariance is estimated from test-set energies
  (`train_energy_matrix=energy_matrix`, labelled a proxy in `lad_qbat_edge.py`) rather than
  from the training set as described in Section 3.6.1.
- The dashboard's single-session BAT vote (`dashboard/bat_predict.py`, `dashboard/app.py`)
  thresholds the **mean** energy of a window, which rarely exceeds the per-line EM-GMM
  threshold; it is a display path and does not affect the batch pipeline or any claim.
